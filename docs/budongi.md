# 부동이 · 부동산 데이터 통합·정제와 질의응답 MVP

2023.08.01–10.14, 발표를 포함한 3인 팀 프로젝트입니다. 초기 개발은 09.11까지이며 서울·경기·인천 청약·실거래·시설 정보를 연결했습니다. 데이터야놀자 2023에서 발표했습니다.

## 문제와 역할

청약 정보만으로 가격과 주변 여건을 함께 판단하기 어려웠습니다. 출처별 주소·좌표·누락 정보가 달라 데이터 연결과 보완이 필요했습니다.

청약 크롤링은 단독 수행했고, 전처리·초기 EDA는 팀과 분담했습니다. 후반 분석 결론 도출을 주도하고 회귀 모델링과 템플릿 기반 Azure OpenAI MVP 환경 구성을 담당했습니다. GPT 입력 문서·프롬프트는 공동 작업이며 주변 시설 수집은 팀원 담당입니다.

## 데이터 처리

청약홈 API/크롤링 기록 3,347건, 네이버 부동산 실거래 수집 기록 52,186건을 주변 시설 자료와 주소·좌표 기준으로 연결했습니다. 지하철 766건, 병원 71,052건, 대학 2,057건, 공원 18,335건은 서로 다른 원천 기록 규모이며 합계나 최종 행 수로 쓰지 않습니다.

1. 원천 수집과 주소 매핑
2. 오탈자·결측의 수작업 확인 및 보완
3. 중복·이상치 정제와 좌표 기반 시설 거리 피처 구성
4. EDA·회귀 모델링, 청약·입지 정보의 GPT 입력 문서 요약

| 팀 메인 데이터셋 | 결과 |
|---|---|
| 정제 전 |3,296행·50열|
| 정제 후 |3,239행·71열|
| 중복 제거 |57건|
| 주소 분리 성공률 |98.36%|

주소 분리 성공률은 전체 데이터 정확도가 아닙니다. 이 값은 2023년 팀 결과이며 이후 개인 고도화 87열 버전과 구분합니다. 자동 재수집·운영 파이프라인을 구축한 결과로 확대하지 않습니다. 시설 거리는 보행시간이 아닙니다.

## 분석과 서비스 활용

평당 공급액 XGBoost 저장 출력은 R² 0.9728, RMSE139.16, MAE76.10입니다. 별도 모델 입력 2,853행·137열에서 RFE 피처 선택 후 80:20 분할(random_state42)을 사용했습니다. 평가 분할을 early stopping에도 사용했으므로 독립 최종 테스트나 교차검증 평균이 아닙니다. R²를 정확도로 쓰지 않습니다. RMSE/MAE의 원 데이터 산출 단위는 직접 확인하지 않아 단위를 추정하지 않습니다.

Azure MVP는 `azure-search-openai-demo` 템플릿 기반입니다. 청약·입지 요약 문서를 질의응답에 활용했으며 현재 운영 서비스를 뜻하지 않습니다.
